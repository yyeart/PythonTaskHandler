## Функционал
Реализована система обработки задач:
- у задачи есть идентификатор, описание, приоритет, статус, дата создания
- задачи можно получать из нескольких источников
- задачи складываются в ленивую коллекцию (очередь)
- очередь поддерживает фильтрацию и ограничения
- задачи обрабатываются воркерами асинхронно
- для разных диапазонов приоритетов используются разные обработчики

## Основные сущности
### `Task`
Модель задачи с полями:
- `id`
- `description`
- `priority`
- `status`
- `created_at`

Вычисляемое поле:
- `full_info`

Свойство:
- `is_executable`

Особенности:
- `id` является константным полем
- `description` должен быть непустым
- `priority` должно быть в диапазоне от 1 до 10
- `created_at` доступен только для чтения
- `status` меняется только по разрешенным переходам

### Дескрипторы
В проекте используются дескрипторы для валидации и ограничения доступа:
- `Const` - неизменяемое значение
- `NotEmptyString` - строка с минимальной длиной
- `IntRange` - числовая валидация диапазона
- `CreatedAt` - read-only поле
- `FullInfoDescriptor` - описание задачи

### Источники задач
- `FileSource` - читает задачи из JSON-файла
- `GeneratorSource` - генерирует задачи случайным образом
- `ApiSource` - мок HTTP запроса

Все источники реализуют контракт `TaskSource`

### Очередь задач
`TaskQueue` - ленивая, повторно итерируемая коллекция<br>
Поддерживает:
- добавление источников
- фильтрацию по статусу или приоритету
- ограничение количества задач

Операции можно комбинировать цепочкой

### Обработчики задач
Разделены по приоритетам:
- `CriticalTaskHandler`
- `StandardTaskHandler`
- `LowPriorityTaskHandler`

Они:
- проверяют, можно ли обработать задачу
- переводят статус задачи в `In_progress`
- после успешной обработки в `Done`

### Асинхронный исполнитель
`TaskExecutor`:
- запускает пул воркеров
- кладет задачи в асинхронную очередь
- выбирает первый подходящий обработчик
- ведет статистику выполнения
- в случае ошибки выполнения помечает задачу как `Failed`

### Дополнительные классы
- `AsyncTaskQueue`
- `ExecutionSession`
- `ExecutionStats`

## Алгоритм работы
1. Пользователь запускает CLI
2. Программа создает набор источников задач
3. Источники передаются либо в `TaskQueue`, либо в `TaskReceiver`
4. Очередь формирует ленивое представление задач
5. Пользователь может:
   - посмотреть задачи
   - отфильтровать по статусу и приоритету
   - ограничить число выводимых задач
   - запустить асинхронную обработку выбранного набора
6. При обработке исполнитель:
   - забирает задачу из очереди
   - находит подходящий обработчик
   - выполняет задачу в `ExecutionSesssion`
   - обновляет статус и статистику
   - логирует
7. После завершения работы выводится сводка

## Установка и запуск
1. Склонируйте репозиторий:
```bash
git clone https://github.com/yyeart/pythontaskhandler.git
cd PythonTaskHandler
```
2. Настройте окружение:
```bash
python -m venv .venv
source .venv/bin/activate # Для Linux/macOS
.venv\scripts\activate # Для Windows
```
3. Установите зависимости:
```bash
pip install -r requirements.txt
```
4. Запустите приложение:
```bash
python -m src.main
```

## Особенности и ограничения
- `ApiSource` является лишь моком и не выполняет никаких HTTP запросов
- `FileSource` ожидает файл со списком словарей задач
- Статусы задач и их переходы ограничены определенным набором в `src/core/constants.py`
- `TaskQueue` повторно итерируема и строит новые ленивые представления при каждом запросе
- Асинхронный исполнитель пользуется ограниченной очередью
- `full_info` можно переопределять
- При ошибке обработки задача помечается как `Failed`
- Задачи, для которых не найден подходящий обработчик, скипаются (это видно в финальной сводке статистики)

## Допущения
- `TaskExecutor` работает только с объектами, реализующими контракт `TaskHandler`
- Приоритеты работают так: 1 - самый неважный, 10 - самый важный
